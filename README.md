# Bunker — «Подземный комплекс»

Браузерная экспедиция по русскоязычному [ТЗ](docs/spec/bunker_technical_spec_ru_v1.md). Текущий код — **инженерный стенд 0.2**, баланс **1.1**, схема снимка **2**. Полная игровая сцена и экспедиция ещё разрабатываются.

Реализованы данные принятого комплекса, PCG32, фазовый секундный цикл, вода/тепло/лестницы, насосы и их неисправности, сигналы датчиков и реле, алгоритмы ЦБУ, питание/батарея, таймеры осмотра и самодиагностики. Служебный интерфейс содержит телеметрию, команды экспериментов, сохранение в IndexedDB и импорт/экспорт JSON. Сборка TypeScript/Vite, 34 теста Vitest и все 3 браузерных сценария проходят в [GitHub Actions](https://github.com/KindPinocchio/Bunker/actions/runs/43264467462). Подробности — в [отчёте CI](docs/verification-ci-2026-11-12.md).

## Запуск без установки пакетов

Требуется Node **24**; проверено на `24.22.1`, npm `11.9.0`.

```bash
cd /workspace/Bunker
npm run test:local
npm run demo -- --scenario flood --ticks 30
npm run demo -- --scenario cold --ticks 60
npm run demo -- --scenario blackout --ticks 20 --output .cache/blackout.json
```

Проходят **41 локальная проверка**: 9 температурной функции и 32 инженерных систем. Сценарии запускают то же численное ядро на принятых исходных данных, выводят изменения и проверяют точный повтор по seed/журналу. Это стенд разработчика; он не заменяет валидацию Zod или браузерные проверки.

- `flood`: 12 см воды в спальне 2; автоматика включает дренаж и изоляцию. На тике 10 закрываются дренажные вентили сухих комнат, меняя полезную долю откачки.
- `cold`: изолированная спальня охлаждена до 0 °C; ЦБУ запускает отопление по сигналу датчика.
- `blackout`: исчезает внешняя сеть, затем выключается выход батареи; после возврата сети восстанавливается сохранённый ручной режим двери.

## Браузерное приложение

В обычной среде с доступом к npm:

```bash
npm ci --cache .cache/npm
npm run check
npm run test:sim
npm run build
npm run dev
```

Открыть адрес Vite, обычно `http://localhost:5173`. Для собранной версии — `npm run preview`. Версии пакетов и транзитивных зависимостей закреплены в `package-lock.json`.

При ограничении сети сборку можно получить из артефакта `bunker-dist` в GitHub Actions, распаковать в `dist` и выполнить `npm run preview:static`. Этот сервер использует только стандартную библиотеку Node. В текущей песочнице запуск локального HTTP-сервера отдельно ограничен `listen EPERM`, поэтому браузерные тесты идут на GitHub runner.

`npm run test:e2e` запускает Playwright против собранной версии на порту 4173. Для установки его браузера: `npx playwright install --with-deps chromium`. В локальной Linux-среде используется системный `/usr/bin/chromium`, если он есть; другой путь можно передать через `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. CI использует Chromium Playwright и Ubuntu 24.04. Firefox и целевые FPS ещё не проверены.

В служебном интерфейсе можно задать seed, запустить/приостановить время, менять вентили и режимы дверей, выводить насосы из эксплуатации, переключать питание и задавать контрольные состояния. Истинные значения и удалённые команды доступны только в этом режиме разработчика. Обычный игровой интерфейс будет ограничивать сведения и доступ по ТЗ.

Скрытая вкладка автоматически ставит стенд на паузу. Пауза сохраняет долю незавершённой секунды; загрузка не начисляет офлайн-время и оставляет интерфейс на паузе. Один локальный снимок хранится в IndexedDB `bunker-development`; JSON содержит состояние, версии, RNG и журнал команд. Несовместимая версия схемы/баланса или источник данных отвергается до замены сеанса; загрузчик и продолжение часов/действий проверяются Vitest и браузерными сценариями.

## Текущие границы

- Рост/распространение колоний, пыльца, крысы, опасности игрока и контактные дозы пока не подключены. От биологической фазы работают только обратимые эпизоды инженерных компонентов; исходная генерация очагов и носителей появится позже.
- 72 свободные находки, 41 место обыска, перемещение и полные инвентарные действия ещё не реализованы. В ядре есть 86 установленных компонентов и 5 стартовых вещей одежды.
- Схема помещений и редактирование истинных значений — диагностические инструменты. Финальная игра не получает карту или удалённое управление.
- Прошли численные проверки, полный `tsc`, Vitest и сборка Vite. Результат браузерных проверок приведён в отчёте CI. Это ещё не полная приёмка AC01–AC38.
