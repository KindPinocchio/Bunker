# Температурная функция грибницы — решение 1.1

Принято 11 ноября 2026 года по поручению пользователя самостоятельно определить функцию. Действующие источники: исходное [ТЗ 1.0](spec/bunker_technical_spec_ru_v1.md), дополненное этим решением, и [баланс реализации 1.1](../data/bunker_balance_v1_1.json). Решение закрывает неопределённость `F(T)` в приложениях A.8/A.9. Остальные правила исходного ТЗ сохраняются.

Температура `T` измеряется в °C. Безразмерный множитель:

```text
F(T) = 0,             T ≤ 5 или T ≥ 50
       (T − 5) / 25,  5 < T ≤ 30
       (50 − T) / 20, 30 < T < 50
```

Функция непрерывна, лежит в диапазоне 0–1, имеет единственный максимум при +30 °C. Нижняя и верхняя границы взяты из ТЗ. Положение максимума сохраняет три контрольных времени роста из [проверки баланса](spec/bunker_balance_validation_v1.md).

| T, °C | F(T) | Рост, п.п./с | Время с 1% до 100%, с |
| --- | --- | --- | --- |
| 5 | 0 | 0 | Рост остановлен |
| 10 | 0,2 | 0,066 | 1500 |
| 15 | 0,4 | 0,132 | 750 |
| 20 | 0,6 | 0,198 | 500 |
| 25 | 0,8 | 0,264 | 375 |
| 30 | 1 | 0,33 | 300 |
| 35 | 0,75 | 0,2475 | 400 |
| 40 | 0,5 | 0,165 | 600 |
| 45 | 0,25 | 0,0825 | 1200 |
| 50 | 0 | Рост отсутствует | Начинается отмирание |

Время считается для уже существующего очага с живым покрытием 1% на момент `t = 0`, при постоянной температуре, без поедания, обработки и ограничений свободных вещей. Это время **99 процентных пунктов роста**, а не роста с нуля. Новому очагу в тике появления рост не начисляется: его первый шаг роста приходится на следующий тик. Сравнение с пределом выполняется с допуском `1e-9`; при достижении предела значение нормализуется к нему.

## Применение в симуляции

- **Рост существующей колонии:** `g = 0.33 × F(T)` п.п./с. `I_next = min(cap, I + g × dt)` только при `I > 0` и `5 < T < 50`. Предел `cap` выбирается по существующим правилам объекта: 100% либо 30% для свободной вещи. Рост не создаёт колонию на чистой поверхности.
- **Передача по разрешённому ребру:** `p = 0.01 × weight × F(T_target)` за один секундный тик. Источник должен иметь `I_source > 0` и `5 < T_source < 50`; цель должна допускать заражение и быть незащищённой. Процент источника и `F(T_source)` дополнительно не умножаются. После успеха чистая цель получает 1%; несколько успехов за тик не складываются.
- **Образование пыльцы:** `p = 0.0015 × (I / 100) × F(T)` за один секундный тик активного источника. Сохраняются лимиты комнаты/мира, срок жизни и остальные правила облаков. Функция не меняет уже существующее облако.
- **Повреждение оборудования:** при `5 < T < 50` скорость равна `damageRate × I / 100` п.п./с. Множитель `F(T)` сюда не добавляется. То же правило отсутствия дополнительного температурного множителя действует для заданных эффектов плесени на насосы и обратимых эпизодов оборудования; их формулы остаются исходными.
- **Покой и отмирание:** при `T ≤ 5` живая плесень сохраняется, но не растёт, не передаётся и не повреждает оборудование. При `T ≥ 50` действует отдельная таблица отмирания из баланса: на ровно +50 °C это 0,1 п.п./с. Нулевой `F(T)` не означает мгновенное уничтожение колонии.
- **Контактное отравление:** определяется живым процентом и химзащитой, без множителя `F(T)`. Живая плесень остаётся контактным источником и в холоде, и во время отмирания. Заморозка состояния вещей в рюкзаке/руках остаётся отдельным правилом.

Все вероятности приведены для исходного шага `dt = 1 с`. Их нельзя пересчитывать по FPS. Температура и процент здесь являются истинными физическими значениями, а не сигналами датчиков.

## Код и проверки

[Реализация на TypeScript](../src/sim/fungus-temperature.ts) создаёт чистую функцию из `fungus.temperature_response`. Она проверяет конечность/порядок параметров один раз при создании и отклоняет нечисловую температуру; RNG, время и браузер не используются.

[Проверки](../tests/sim/fungus-temperature.test.mjs) выполняются на Node 24 без установки зависимостей:

```bash
node tests/sim/fungus-temperature.test.mjs
```

Они проверяют границы, опорные значения, три контрольные траектории 500/300/600 секунд, неизменность остальных коэффициентов и контрольные суммы исходного пакета. Полное взаимодействие грибницы с графом, облаками и оборудованием будет проверяться при реализации соответствующих систем.
